## Release immutability verification

The package digest above proves the bytes that were verified during release, but this repository record does **not** independently prove that GitHub's immutable-release setting was enabled for `v0.1.10`.

Repository administrators must verify the release in GitHub and record the result in the repository-security checklist. If immutable releases were not enabled when v0.1.10 was created, enabling the setting later protects future releases but does not retroactively make this release immutable.

See `docs/operations/repository-security.md`.

## Historical pre-release incident

Earlier on 2026-08-19, before the handoff Worker was deployed, a split-origin diagnostic created and uploaded a disposable share through the production relay but the generated handoff hostname returned HTTP 404. At that point the release was correctly blocked.

The handoff Worker was subsequently deployed and verified, the strict live gate passed, the full CI matrix was rerun, and the package was then published. The earlier 404 is retained here only to explain the release chronology.

## Deployment order

For v0.1.10 and later releases that introduce a new browser handoff dependency, deploy and verify the handoff Worker **before** publishing a creator package that generates links to it. This prevents newly generated links from pointing at an unavailable recipient endpoint.

Existing v0.1.9 links remain the legacy rollback baseline.

See `docs/operations/cloudflare-deployment.md` for deployment and rollback procedures.
