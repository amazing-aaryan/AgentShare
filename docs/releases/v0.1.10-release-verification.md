# AgentShare v0.1.10 Release Verification

Date: 2026-08-19  
Release candidate branch: `fix/handoff-trust-and-lifecycle`  
Status: **BLOCKED — NOT RELEASED OR PRODUCTION READY**

## Blocking condition

The independent production handoff origin is not serving the v0.1.10 handoff
Worker yet. A live split-origin diagnostic on 2026-08-19 created and uploaded a
real disposable share through the production relay, then fetched its generated
handoff URL at:

`https://agentshare-handoff.carnation-vermicelli.workers.dev`

The handoff request returned HTTP 404. The release must not be published while
that hostname is unavailable because the v0.1.10 creator CLI generates links on
that origin by default.

The same live diagnostic confirmed that the production relay accepted the new
cross-origin metadata flow: create/upload/replay/expiry behavior and browser
metadata CORS passed against
`https://agentshare-relay.carnation-vermicelli.workers.dev`.

## Completed candidate gates

- The preceding release-candidate head passed the six-job CI matrix on Ubuntu,
  macOS, and Windows with Node.js 22 and 24.
- Formatting, TypeScript/ESLint, build, coverage tests, package smoke test,
  edge-runtime handoff, relay Worker dry-run, handoff Worker dry-run, and
  high-severity dependency audit passed in that matrix.
- The v0.1.10 URL parser and creator flow separate handoff and relay origins while
  retaining v0.1.9 legacy-link parsing.
- Creator review/reuse/revocation regressions are covered by automated tests.
- Production relay CORS for handoff-origin metadata validation was exercised
  successfully in the live diagnostic.
- The strict release script now requires distinct live HTTPS relay and handoff
  origins and always requires both real recipient agents.

These completed items do not override the blocking live handoff failure. A fresh
full CI run is also required after the final release-gate hardening commits.

## Required before release

- Deploy `apps/handoff` to the intended production handoff hostname.
- Record the exact handoff Worker deployment version and a rollback target.
- Verify the live handoff page returns the expected no-store, no-referrer,
  nosniff, frame-denial, and relay-scoped CSP headers.
- Run `npm run test:release` with both production origins and authenticated
  reviewed Codex and Claude installations; require zero skipped real-agent tests.
- Re-run the complete six-job CI matrix on the exact release candidate commit.
- Build and publish the immutable `agentshare-0.1.10.tgz` asset only after the
  handoff Worker and strict live gate pass.
- Record package byte size and SHA-256, then verify an anonymous download against
  that digest.
- Perform a fresh isolated install from the published asset and verify package
  name/version/CLI usage.
- Exercise a disposable live creator → handoff page → hidden recipient prompt
  flow using the published package, then revoke or expire the share.
- Record the final relay deployment version if the relay was redeployed.
- Update this status to **RELEASED AND DEPLOYED** only after every gate above has
  evidence attached.

## Deployment order

For v0.1.10, deploy and verify the independent handoff Worker before publishing
the creator package. Publishing the package first could allow clients to create
links whose browser endpoint is not live. Existing v0.1.9 links remain
independent of the new handoff Worker and are the rollback baseline.

See `docs/operations/cloudflare-deployment.md` for the deployment and rollback
procedure.
