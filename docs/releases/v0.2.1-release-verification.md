# AgentShare v0.2.1 Release Verification

- Status: **release candidate in progress**
- Release date: 2026-08-29
- Package version: `0.2.1`
- Base feature merge: PR #10, master commit
  `4bf9dad62523414a030c3bb4ba29fa376bfb106b`
- Release-candidate branch: `release/v0.2.1-candidate`

This patch exists to ship the Codex recipient compatibility policy introduced by
PR #10. It replaces Codex's exact-version allowlist with a minimum supported
version plus fail-closed runtime capability checks, so routine newer Codex
releases are not rejected solely because their version number changed.

## Scope and carried-forward evidence

The changed security surface in v0.2.1 is the **Codex compatibility preflight**:

- Codex CLI must be recognizable and version `>= 0.145.0`;
- `codex exec --help` must still advertise every isolation control AgentShare
  relies on;
- the restrictive Codex launcher arguments and permission configuration are
  unchanged from the previously reviewed launcher profile;
- AgentShare still respects a Codex runtime refusal when the requested sandbox
  cannot be enforced.

The Claude Code adapter, its launcher arguments, and its exact-reviewed version
policy are unchanged in this patch. The most recent recorded Claude isolation
evidence therefore carries forward; v0.2.1 does not claim a newly reviewed
Claude release.

The blind-relay protocol, Durable Object storage schema, migrations, and
ciphertext lifecycle are also unchanged. The production relay does not need a
code or migration deployment for this handoff/package-only patch.
