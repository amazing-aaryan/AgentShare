This patch ships the Codex recipient compatibility policy introduced by PR #10.
It replaces Codex's exact-version allowlist with a minimum supported version
plus fail-closed runtime capability checks, so routine newer Codex releases are
not rejected solely because their version number changed.

GitHub currently reports the v0.2.1 release as `immutable: true`,
`prerelease: false`, and the repository's latest release. The release remains
targeted at the exact verified commit above and contains exactly one asset.

## Scope and carried-forward evidence

The changed security surface in v0.2.1 is the **Codex compatibility preflight**:

- Codex CLI must be recognizable and version `>= 0.145.0`;
- `codex exec --help` must still advertise every isolation control AgentShare
  relies on;
- the restrictive Codex launcher arguments and permission configuration are
  unchanged from the previously reviewed launcher profile;
- AgentShare still respects a Codex runtime refusal when the requested sandbox
  cannot be enforced.

The Claude Code adapter, its launcher arguments, and its exact-reviewed version
policy are unchanged in this patch. The most recent recorded Claude isolation
evidence therefore carries forward; v0.2.1 does **not** claim a newly reviewed
Claude release and the full two-agent `npm run test:release` diagnostic was not
claimed as passing for this patch.

The blind-relay protocol, Durable Object storage schema, migrations, and
ciphertext lifecycle are also unchanged. The production relay was deliberately
left in place and was not redeployed for this handoff/package-only patch.
