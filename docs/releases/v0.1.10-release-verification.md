## Release immutability verification

On 2026-08-20, GitHub CLI's official release-integrity verifier independently
verified `v0.1.10` from a GitHub-hosted Actions runner:

```text
gh release verify v0.1.10 --repo amazing-aaryan/AgentShare
✓ Release v0.1.10 verified!
agentshare-0.1.10.tgz  sha256:88a92d2ac668c6b1dcea63fa7b3bb539a18068c7c4b1719dd94f1e3a8df23d9b
```

The verifier loaded the GitHub release attestation and resolved the immutable
release tag to Git object `a24580870fd3f4837c9c47a8cca9e5e5396020f4`. This
closes the historical question about whether the published v0.1.10 release and
asset are immutable.

Repository administrators should still keep release immutability enabled for
future releases. See `docs/operations/repository-security.md`.

## Historical pre-release incident

Earlier on 2026-08-19, before the handoff Worker was deployed, a split-origin
diagnostic created and uploaded a disposable share through the production relay
but the generated handoff hostname returned HTTP 404. At that point the release
was correctly blocked.

The handoff Worker was subsequently deployed and verified, the strict live gate
passed, the full CI matrix was rerun, and the package was then published. The
earlier 404 is retained here only to explain the release chronology.

## Deployment order

For v0.1.10 and later releases that introduce a new browser handoff dependency,
deploy and verify the handoff Worker **before** publishing a creator package
that generates links to it. This prevents newly generated links from pointing at
an unavailable recipient endpoint.

Existing v0.1.9 links remain the legacy rollback baseline.

See `docs/operations/cloudflare-deployment.md` for deployment and rollback
procedures.
